Think of yourself as a senior Python developer and software architect. Write clean, modular,

I will give you the approach for a problem statement, and you need to build a complete frontend

In the problem statement, the input is a YouTube video link or any equivalent source, and an
on-screen dialogue text is given. On-screen dialogue is basically when the character should be
on camera while saying the dialogue. I found out many edge cases for this as well.
My first approach was downloading the video locally, converting the whole audio to text, and
then using fuzzy matching to find out whether the transcription matches the given dialogue and
get that frame. But if the video is too long, like the one given in the PS, which is 55 minutes,
it will take a long time to transcribe everything.
So what I did is, instead of transcribing the whole audio first, I stream the transcription.
Faster-Whisper gives the transcribed segments one by one as it decodes, so after every segment,
I fuzzy-match the words we have so far against the given dialogue and stop as soon as the first
match is found. So if the dialogue is at 5 minutes, only 5 minutes of audio gets transcribed,
not 55.
There is no application-level chunking needed because we process the transcription as a
continuous stream of timestamped words. This allows the dialogue to span across multiple
Faster-Whisper segments without being affected by artificial chunk boundaries.
First, the audio is extracted from the video, then it is streamed through a small
Faster-Whisper model with word-level timestamps.
For matching, I slide a window over the transcribed words. The window size is based on the
dialogue word count, with a tolerance of plus or minus 2 words to handle cases where the ASR
model splits or merges words. Each window is scored using fuzzy ratio.
Since we are using a small model, some words can be transcribed incorrectly. So if the match
score is 80 or above, I treat it as a candidate and run a larger Whisper model only on a
±20-second window around that point to confirm the text and tighten the word timestamps.
If the larger model also matches, meaning its score is not more than 5 points below the first
score, I take its timestamp. Otherwise, I keep the first timestamp and note a warning.
Then, the timestamp of the first word is converted to a frame number and that frame is saved as
an image.
The output should contain:

* Timestamp
* Frame number
* Matched dialogue text
* Corresponding video frame as image

If the same dialogue occurs more than once, the earliest valid occurrence is taken as the answer
since we want the first appearance.

If nothing matches above the threshold, it should report the 3 closest matching windows with
their scores so we can see whether the dialogue text or the video is wrong.
